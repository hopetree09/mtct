# MTCT 演示视频脚本（3 分钟）

> 目标：让面试官在 3 分钟内看懂"解决什么问题、怎么做的、效果如何"。
> 形式：录屏 + 口播字幕，1440×900，30fps。

---

## 录制前置（录制前一天准备好）

```powershell
# 1) 起演示站
python -m http.server 8765 --directory demo/web-app

# 2) 起 API + 控制台
python -m mtct api --port 8000

# 3) 预跑两轮，保证控制台有数据
python -m mtct baseline --serve
python -m mtct run --cases cases/home-layout.yaml cases/coin-layout.yaml cases/trade-layout.yaml cases/login-form.yaml --terminals chromium-1366-dpr1-zh,chromium-1920-dpr1-vi --faults none,bench-001,bench-071 --serve
python -m mtct cluster --run runs/<上一步 run_id>
```

录制检查清单：

- [ ] 浏览器窗口 1440×900，只留一个标签页，隐藏书签栏
- [ ] 清空 `runs/` 里太旧的目录（只留 2–3 轮，页面干净）
- [ ] 字体放大到 110%，录屏后观众看得清
- [ ] 关掉微信/QQ/邮件通知
- [ ] 演示站与 API 都已启动，浏览器先打开 `http://127.0.0.1:8000/ui/`

## 分镜脚本

### 0:00–0:20 开场：问题（口头 + 一张图）

**画面**：演示站 `http://127.0.0.1:8765/` 首页，鼠标切换语言（中文 → 越南语）。

**旁白**：

> "我在某数字资产交易平台实习时主要做 UI 测试，写了 1000 多条用例。每个版本要在三种浏览器、中文英文越南语、弱网下各跑一遍。最痛苦的不是点，是盯着几百张截图判断哪个差异是真 bug——所以我想把执行和初筛都自动化。"

**字幕**：`1000+ UI 用例 / 3 语言 / 3 浏览器 / 弱网`

---

### 0:20–0:50 被测对象 + 故障注入

**画面**：浏览器地址栏输入
`http://127.0.0.1:8765/?lang=vi-VN&fault=layout-card-overflow#/home`
页面出现卡片撑破、文字溢出；再刷新去掉 `fault` 参数恢复。

**旁白**：

> "被测对象是我自己写的一个演示站：交易所形态、三语可切换。它内置 120 个确定性缺陷开关，每个都有标准答案，这样才能量化'到底抓到了多少'。"

**字幕**：`自研演示站 · 22 条语义故障 + 120 条基准集`

---

### 0:50–1:30 执行与矩阵

**画面**：切到控制台 `http://127.0.0.1:8000/ui/#/runs`，点最近一轮 Run，展示矩阵热力图 + 顶部统计。

**旁白**：

> "测试系统通过 HTTP API 提交任务，后台异步执行：每个终端一个浏览器上下文，注入分辨率、DPR、语言、弱网。跑完的结果落库，控制台能看到终端 × 用例的矩阵：绿色通过、红色失败。"

鼠标从绿块划到红块，停一下。

**字幕**：`FastAPI + 异步队列 + SQLite · 幂等 / 取消 / 增量落库`

---

### 1:30–2:10 证据链（最重要的一段）

**画面**：点击一个红色块，抽屉打开：断言明细（逐条规则）→ 向下滚动到"证据"四图：实际截图、基线截图、差异可视化（红色高亮）、变化区域裁片。

**旁白**：

> "点开失败用例，先看是哪条断言挂了：横向溢出、元素超出视口、相邻卡片重叠。再看证据：基线、实际、像素差异、变化区域裁片。**不是一句'检测到了'，而是能直接定位到哪块像素变了。**"

**字幕**：`断言 + 基线 + 像素 diff + 裁片 = 可复核的证据链`

---

### 2:10–2:45 基准集评测

**画面**：切到终端，跑
`python -m mtct eval --serve`
滚到结束：`检出 120 / 120，recall 100%，基线误报 0`；再打开 `benchmark/<id>/report.md` 展示分类别表格。

**旁白**：

> "为了证明判定有效，我做了 120 例带标签的缺陷基准集：只上规则断言时检出 90%，补上像素比对后 120 例全部检出，基线误报 0。每一步数字都能一键复现。"

**字幕**：`120 例 · 90% → 100% · 误报 0`

---

### 2:45–3:00 归因与 AI 边界

**画面**：控制台 Run 详情页下半部分，根因簇卡片；再切到 `runs/<id>/clusters.md`。

**旁白**：

> "最后是归因：同一类失败会自动聚成根因簇，这轮 12 条失败压成了 4 个根因，人只看 4 张卡片。AI 判定层也接好了，只处理像素已经变化、但性质拿不准的样本——AI 不做最终裁决，拿不准一律交人工。"

**字幕**：`12 条失败 → 4 个根因 · AI 只做定性`

## 剪辑要点

| 段落 | 处理 |
|---|---|
| 跑测试的等待 | 4–8 倍速，角落加"加速中"角标 |
| 控制台操作 | 鼠标移动放慢，点击前停顿 0.5s |
| 关键数字 | 放大 + 高亮描边（100%、0 误报、4 个根因） |
| 全片 | 加中文字幕；不要 BGM 压过旁白 |
| 导出 | 1080p、H.264，文件控制在 30MB 内，方便发邮箱 |

## 一句话封面文案
